# ChatCraft

A ChatGPT- and Claude-style AI chat app that runs entirely in your browser and talks to real AI providers with your own API keys (BYOK — bring your own key).

## What it is

ChatCraft is a reconstruction of the public chatgpt.com and claude.ai interfaces — the familiar two-pane layout, streaming responses, markdown rendering, and chat management — as a single self-contained HTML file with no build step. It is **not** an official product and has no affiliation with OpenAI or Anthropic. The UI patterns are **documentation-based**: rebuilt from publicly documented interface behavior, not from scraped or decompiled proprietary code. Real inference requires your own API key — without one, the app is labeled "setup required."

As part of the same research task, dalica.pkarma.com was read in full. It is an open-source (MIT/Apache-2.0) Rust photo organizer, not an AI chat application, so it informed tooling choices only and is not reconstructed here.

## Features

- **Real AI, two providers** — OpenAI (`/v1/chat/completions`) and Anthropic (`/v1/messages`), with streaming (SSE), stop, and regenerate. Model picker includes current models plus a custom model ID field.
- **BYOK with privacy** — keys live in page memory by default; opt-in "remember" stores them in localStorage. Keys are sent only to the provider endpoint you choose.
- **Conversations** — sidebar with new chat, search, rename, delete; titles auto-derived from the first message; state persisted in localStorage.
- **Markdown rendering** — escape-first sanitizer, fenced code blocks with copy buttons, headings, lists, links, blockquotes, bold/italic.
- **Artifact preview panel** — html/svg code blocks get a Preview button that opens a sandboxed side panel rendering the code.
- **Edit your message** — re-send from any earlier point in the conversation.
- **Look & feel** — dark/light theme toggle, and a style toggle switching between ChatGPT-style and Claude-style palettes/typography.
- **Mobile** — slide-over sidebar, responsive layout.
- **Error handling** — friendly messages for 401/403 (invalid key, pointing to Settings), network errors, and empty responses.

## Verified behavior (automated QA, mocked transport)

The following were exercised end-to-end through the real UI with a mocked fetch: streaming render, stop mid-stream (partial text kept, marked *(stopped)*), regenerate, edit-and-resend, markdown/code block rendering, artifact preview, 401 error handling, OpenAI and Anthropic request bodies (correct URLs, models, auth headers), Anthropic-format SSE parsing, XSS safety (user content is escaped), persistence across reload, chat search/switch/rename/delete, theme/style toggles, Escape-closes-modal, no-key send prompts for key, mobile sidebar collapse.

## Setup required (not verifiable without a key)

Real end-to-end inference against the live OpenAI/Anthropic APIs was not exercised in QA because no API key was available. To use it for real: open Settings, paste an OpenAI or Anthropic API key, and send a message. Provider details verified against current documentation — OpenAI models ([gpt-5.5 family](https://developers.openai.com/api/docs/models/gpt-5.5), [all models](https://developers.openai.com/api/docs/models/all)); Anthropic models ([Sonnet 5.5 overview](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), [model IDs and versions](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)) — with the `anthropic-dangerous-direct-browser-access` header for browser calls.

The hosted preview (perplexity.ai/computer/a/...) is deployed from a memory-only variant generated by `preview-build.py`, because the sandboxed preview iframe blocks web storage: the app there shows a "session-only" notice and the Remember-keys checkbox is disabled. The repository/GitHub Pages version uses normal persistent storage.

## Known gaps vs the real chatgpt.com / claude.ai

No login/accounts, no file uploads, no web search, no voice input, no projects or saved artifacts gallery (only the inline preview panel), no token usage metering.

## Tech

One `index.html` — vanilla JS, no dependencies, no build. Ships as a static file.
