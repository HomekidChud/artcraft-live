3D movie studio in your browser

Plan it, build it, animate it, export it.

VideoCraft is a ten-workspace browser studio for making 3D short films: paint assets, design characters, build scenes, add cinematic particle FX, import GLB models, keyframe animations across shots, and export a frame-accurate WebM movie. This page is the manual — for humans and for AI agents.

Quick start

  1. Open the studio — index.html. Press Starter scene or 3D race movie in the top bar to load a ready project you can pull apart.
  2. Build a shot — in the Scene workspace, add boxes, spheres, drawings and characters, then position them with the gizmo.
  3. Add FX — add a fire, smoke, sparks, explosion or fountain object anywhere in the scene.
  4. Animate — in the Animate workspace, set a keyframe (position/rotation/scale per object), scrub the timeline, move things, key again. Add more shots and reorder them into a movie.
  5. Export — use Export movie in frame-accurate mode. Leave the range fields blank for the whole movie, or fill them to export one section at a time.

Everything runs locally in your browser — no account, no upload. Projects save as a small .videocraft JSON file you can reopen, share, or hand to another tool.

Workspaces

The left rail switches between ten workspaces. The four hands-on ones are:

Draw — a 2D paint canvas. Brush size, softness, colour and shapes. Saved drawings become textured planes you can place in 3D scenes.

Cast — a parametric character builder: head, hair, eyes, brows, nose, mouth, torso, arms, legs, colours. Characters come with a simple rig (head/arm/leg pivots) you can keyframe.

Scene — the 3D stage. Add primitives, your drawings, characters, GLB models and FX objects. Drag with the gizmo, tweak colour/opacity/scale in the props panel.

Animate — timeline and shots. Keyframe every object channel, play the shot or the whole movie, and manage the shot list that becomes your film.

The other six (Plan, Design, Storyboard, Sound, Assets, Deliver) are lighter production tabs — checklists, asset cards, storyboard frames, audio clip planning and a delivery checklist. The look of the render (background colour, fog, vignette, grade) lives in the Scene workspace's Look panel.

FX engine

FX objects are GPU particle systems — deterministic, timeline-driven, and identical between preview and export. Each has an intensity, size, speed and start time you can animate like any other object.

PresetFeelNotes
fireLooping embers and flameGood default for torches, campfires, engines
smokeSlow, soft, loopingNon-additive — reads well over bright backgrounds
sparksFast falling sparksWelding, electrical damage
explosionOne-shot blastBurns out once per fxStart; set the start time to trigger mid-shot
fountainLooping upward jetsWater, confetti, magic

Because particles are seeded deterministically from the timeline, scrubbing back and forth shows the same particles — no randomness between preview and export.

GLB models

The Scene workspace has a GLB import in the props panel. Models are loaded, cached per-project and re-fetched automatically before any export starts — a broken URL aborts the export with a clear message instead of silently rendering a missing model.

Static models only. VideoCraft renders GLBs as placed props: geometry, materials and textures. Rigged/skinned animation inside the GLB is not played back. Animate a GLB by keyframing its position, rotation and scale like any other object.

Phone & touch

On screens under 760px wide the studio flips to a viewport-first layout: the 3D view fills the screen and every side panel becomes a slide-in sheet.

  • Panels — a floating dock on the right edge (Tools / Cast / Props / Shots / Animate) opens the panels for the workspace you're in. Tap the dimmed backdrop or press Esc to close.
  • Timeline — the Timeline dock button slides it up from the bottom.
  • Touch targets — buttons, tools and sliders are enlarged to comfortable touch sizes.
  • Canvas gestures — one finger orbits, and the gizmo handles are touch-sized too.

Export

Two modes, one button. The export panel is in the Animate workspace.

Real-time recording

Records the canvas with MediaRecorder while the movie plays — includes audio, but the timing depends on your device keeping up. Keep the tab visible and foregrounded.

Frame-accurate export

Renders every frame through WebCodecs (VP8, WebM) and muxes a file — identical frames regardless of device speed. Audio clips are mixed offline and muxed in as an Opus track, so exports are no longer video-only.

  • Resolution — 720p or 1080p, plus the project's export aspect.
  • Quality — 8 / 4 / 2.5 Mbps.
  • Range start / end (seconds) — export a section of a long movie. Blank = whole movie. Sections restart at timestamp zero with their audio offset to match, so you can render a 30-minute film in stress-free chunks.
  • Full-length movies — in browsers with the File System Access API (Chrome, Edge, Opera, and Chromium-based mobile), the export asks where to save and streams the movie to that file as it renders. Video memory stays bounded, so a feature-length film exports in one pass (decoded audio scales with the soundtrack — see the audio note below). Browsers without it fall back to keeping the video in memory, which is only safe for shorts.

Stitching sections

Sections are standalone WebM files — do not join them by concatenating bytes. Use a remuxing tool, e.g. with ffmpeg:

printf "file 'part1.webm'\nfile 'part2.webm'\nfile 'part3.webm'\n" > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c copy movie.webm

Each section starts on a keyframe and carries its own audio, so concat needs no re-encode and the soundtrack comes along for free.

Export speed: the frame-accurate renderer keeps the encoder pipeline saturated and yields to the UI periodically, so a 720p export typically renders faster than real time on a modern laptop — but plan around real-time-ish speeds on phones.

Honest limits

VideoCraft is a browser studio for stylised 3D films, not a replacement for a render farm. Things you should know before promising anyone a feature-length movie:

  • Memory — now much less of a wall. In browsers with the File System Access API, frame-accurate export streams to a file you pick as it renders: a feature-length movie no longer buffers the whole video in RAM (decoded audio is the exception — see below). In browsers without it (Safari, Firefox), the export still keeps the compressed video in memory — keep those to shorts, or export in sections.
  • Audio works in both export modes now. Frame-accurate export mixes your audio clips offline in 30-second blocks (the mix buffer stays small at any length) and muxes them in as Opus. Undecodable audio files are skipped with a note rather than aborting the render. One caveat: every referenced audio file is decoded up front and held while windows still need it — peak RAM scales with the combined decoded soundtrack, and a one-hour stereo track is over 1 GB — so keep individual audio files to a few minutes (per scene or per shot) and add a feature-length continuous soundtrack with ffmpeg after stitching, if you need one.
  • Section joins add ~20 ms of audio padding each. Opus rounds each section's audio to whole packets, so concatenating sections leaves a tiny gap per join — about 1 per section. The one-pass streaming export has no joins, which is the recommended path for long films; sections are for browsers without the save-file dialog or for resumable renders.
  • Rendering time is the real cost of length. A 90-minute film is ~162,000 frames at 30 fps; at faster-than-real-time speeds that is still hours. Stop export keeps the partial file, and section export remains the restartable path for very long films.
  • The >300s warning now only appears in the in-memory fallback (browsers without the save-file dialog). Treat it as "use sections or a streaming browser".
  • Static GLBs only — rigged GLB animation is not played back.
  • No Marvel movies. There is no character mocap, no path-traced global illumination, no crowd systems. What it does — stylised 3D films of any length with FX, camera work and sound — it does well.

For AI agents

VideoCraft is automatable from a browser driver (Playwright, Puppeteer, CDP). The UI uses stable IDs everywhere; there is no login, no server and no API to call — the app is the interface.

Project file format

Projects are a single JSON file (extension .videocraft or .json). Top-level shape:

{
  "version": 2,
  "name": "My film",
  "fps": 30,                      // 10–60, used by the timeline and exports
  "exportAspect": "16:9",
  "drawings": [...],              // painted assets: {id, name, dataURL}
  "glbAssets": [...],            // imported models: {id, name, url}
  "characters": [...],            // parametric rigs (see Cast workspace)
  "shots": [{
    "id": "shot-1", "name": "Shot 1", "duration": 5,
    "sceneObjects": [{ "id": "obj-1", "name": "Fire", "type": "fx",
                       "pos": [x,y,z], "rot": [x,y,z], "scale": [x,y,z],
                       "color": "#fff", "opacity": 1, "fxKind": "fire",
                       "intensity": 1, "fxSize": 1, "fxSpeed": 1, "fxStart": 0 }],
    "keyframes": { "obj-1": { "pos": [{"t": 0, "v": [0,0,0], "ease": "linear"}] } }
  }],
  "activeShotId": "shot-1",
  "audioAssets": [...], "audioClips": [...],
  "studio": {...},                 // production-tab state (plan, storyboard…)
  "look": {...}                    // render look: background, fog, vignette, grade
}

Object type is one of box | sphere | cylinder | cone | torus | plane | engineKit | drawing | character | glb | fx. Rotation is in degrees, positions/scales are plain arrays, keyframe channels are per-object (pos, rot, scale, FX params). The safest way to author one is to build a small project in the UI, Save project, and read the file — or load your JSON through the real Open flow (#file-open) so the app's migration and validation run on it.
